# Новости и материалы для онлайн исследований

Бот собирает правовые новости, статьи, обзоры сервисов, методические материалы и документы об онлайн-опросах, респондентах, безопасности и персональных данных. Платные API и модели не используются.

## Что получает пользователь

Карточка содержит **НОВОЕ**, тип материала, название, тему, короткое объяснение пользы, источник, дату публикации и ссылку. «НОВОЕ» означает впервые присланную ботом находку; старая статья сохраняет свою настоящую дату. Неизвестная дата так и обозначается.

Автоматически приходит до трёх материалов не чаще раза в час. При выборе пакета учитывается разнообразие источников. Остальные находки остаются в очереди; пустые сообщения не отправляются. История доставки ведётся отдельно для каждого подписчика. Если ответ Telegram потеряется после принятого сообщения, повтор технически возможен.

- `/start` — подписка.
- `/latest` — три последних обнаруженных материала, без ограничения годом; повторный показ по явной команде разрешён.
- `/status` — состояние блоков, количество источников и результаты последней проверки дополнительных ресурсов.
- `/stop` — отписка.

## Сбор и обработка

`Источники → collector → PostgreSQL → worker → Telegram`.

Правовые RSS сохраняют прежние тематические правила из `legal_news/topics.json`, исключение судебной практики и суточное перекрытие окна. Первая загрузка правовых RSS ограничена текущим годом и доступным окном издателя.

Дополнительный HTML-контур принимает полезные материалы любого года. За проход проверяется до шести страниц каждого ресурса. Стартовые ссылки дополняются обнаруженными URL; проверенные страницы обычно перечитываются через семь дней, страницы с ошибками — через шесть часов. Это позволяет двигаться по остальным найденным ссылкам при следующих сборах. Пагинация и все архивы сайтов пока не охвачены.

Общая логика в `collector/survey.py` учитывает опросы, анкеты, респондентов, методику, инструменты, безопасность и общие требования к данным. Это объяснимые правила с ограничениями; они могут пропускать неявные связи и принимать спорные материалы. Случайные совпадения в меню не должны служить основанием отбора.

По первой оценке владельца исключены статьи, посвящённые расчёту размера выборки и количества респондентов. Отрицательный пример Testograf закреплён регрессионным тестом (задача T4).

Один материал определяется нормализованной ссылкой; для прежних правовых публикаций дополнительно сохраняется объединение по реквизитам/названию. Обновление текста сохраняет finding и историю доставки, не создавая новую автоматическую рассылку. Полная смысловая дедупликация разных статей об одном событии не реализована.

Ошибки дополнительных страниц записываются по источникам и не останавливают успешные находки. Неизвестные даты, недоступные страницы и сведения о редакциях не додумываются. Авторское слово «разрешённый» в обзоре не превращается в юридический вывод бота.

## Обновление существующего ресурса Coolify

1. Использовать проверенную ветку/коммит из своего репозитория `katyaOMI/legal-news-bot`. До обновления проверить Git Source; прежний README указывал `main`.
2. Сохранить `TELEGRAM_TOKEN`, `SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_POSTGRES` и существующий том PostgreSQL.
3. База остаётся `desk_research`. Миграция добавляет поля и таблицы, не удаляет подписчиков, материалы и историю.
4. Выполнить Redeploy существующего ресурса. Контейнеры: `postgres`, `worker`, `bot`.
5. Существующая задача контейнера `worker`: `python main.py collector`, расписание `0 */3 * * *` (каждые три часа). Не создавать второй сборщик с тем же расписанием.
6. У задачи выполнить Execute Now, затем проверить `/status` и `/latest`. Ручной сбор может привести к настоящим сообщениям подписчикам.
7. Если часть источников недоступна, проверить их счётчики и ошибки; работа остальных продолжается.

Один Telegram-токен должен использоваться одним работающим обработчиком. Для проверки на компьютере не запускать production-бот параллельно.

## Локальный запуск и проверки

Python 3.12 и зависимости из `requirements.txt`. Для PostgreSQL задаётся `DATABASE_URL`, для Telegram — `TELEGRAM_TOKEN`. Реальные значения не писать в команды, документацию и Git.

```text
python main.py collector
python main.py worker
python main.py bot
python -m unittest discover -s tests -v
python checks/audit_release.py .
```

Предпросмотр живых источников без базы и Telegram:

```text
python checks/preview_sources.py --limit 6
```

Он создаёт `work/survey-preview.html`, JSON с карточками и снимок результатов. Эти файлы не публикуются.

После изменения правил можно переоценить те же публичные снимки без новых сетевых запросов: `python checks/preview_sources.py --from-snapshot`. Исходные результаты сохраняются отдельно от актуально принятого набора.

Для сквозной SQL-проверки нужна временная локальная база PGlite и psycopg:

```text
npm install --prefix work/pgcheck --cache work/npm-cache --ignore-scripts --no-audit --no-fund @electric-sql/pglite @electric-sql/pglite-socket
python -m pip install --target work/python-packages --disable-pip-version-check "psycopg[binary]==3.3.6"
node checks/pg_server.mjs
```

В другом окне:

```text
python checks/survey_pipeline.py
python checks/survey_live_replay.py
```

Первый сценарий проверяет синтетические ошибки, даты и доставку. Второй воспроизводит публичные снимки последнего предпросмотра через настоящие таблицы и worker. Оба жёстко ограничены `127.0.0.1:55432`, создают отдельную схему и не отправляют Telegram. Остановка временной базы — запрос к `http://127.0.0.1:55433/shutdown`.

`checks/live_pipeline.py` — отдельный прежний сценарий проверки правовых RSS; для изолированной проверки только старого контура новые HTML-источники следует выключить в его временной базе или замокать отдельно.

## Конфиденциальность

Логирование проходит через `db.redact`: значения секретных переменных, известные форматы ключей, пароли в URL, авторизационные заголовки и явно обозначенные Telegram ID маскируются до вывода. `db.fail_run` и поле ошибки источника сохраняют уже очищенный текст; `/status` дополнительно очищает старые заметки.

Для новых подписок сохраняется только необходимый для доставки chat_id; имя и username не собираются и не печатаются в журналах. Старые записи и старые журналы автоматически не удаляются. Рабочая база остаётся только на сервере.

При `ENABLE_MINI_APP`, не равном `1`, HTTP-корень возвращает лишь технический ответ, без чтения материалов и статистики. `/health` сохраняется. Явное включение `ENABLE_MINI_APP=1` открывает публичную ленту и должно быть осознанным решением владельца.

Дополнительная проверка текущих файлов и доступной истории Git:

```text
python checks/security_audit.py
```

Если Git отсутствует в PATH, можно указать его исполняемый файл через `--git`. Перед историческим аудитом получить актуальные refs из своего репозитория. Отчёт в `work/security-audit.json` содержит пути и названия правил, без значений найденных секретов. Проверка включает принудительно закоммиченные runtime-каталоги, которые обычный обход пропускает. Она охватывает только доступную историю, а не удалённые refs, журналы сервера или хранилища внешних сервисов.

Ни один сканер не гарантирует обнаружение всех произвольных секретов. Перед публикацией также проверяем состав файлов и назначение каждого артефакта. Историю с реальными секретами не переписываем и действующие ключи не отзываем без отдельного решения владельца.

## Память проекта

- `SPEC.md` — согласованное поведение и задачи T1–T3.
- `PRD.md` — цель продукта, пользователь и критерий полезности.
- `AGENTS.md` — правила агента.
- `KANBAN.md` — статусы задач.
- `progress.md` — выполненные вехи и следующий шаг.
- `README.md` — запуск, обслуживание и навигация.

Папка `work/`, зависимости, базы, журналы, .env и ключи исключены из Git. Статическая проверка публикации выявляет известные опасные файлы и форматы, но не заменяет проверку содержимого перед публикацией.
