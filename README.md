# Правовые риски и безопасность онлайн-опросов

Локальная реализация утверждённой [SPEC 2.0](SPEC.md). Состояние публикации и сервера — последняя веха [progress.md](progress.md). Старые сообщения в Telegram не меняются от редактирования локальных файлов.

## Что получает пользователь

Материалы о приватности, безопасности, персональных данных и рисках штрафов при работе из России. Общая методология, NPS, рекрутинг и обновления функций не входят в подборку. Зарубежная новость принимается только с подтверждённой российской связью.

Карточка: заголовок, источник, дата, цитируемый риск, кого может касаться и что проверить. Бот не выдумывает суммы, сроки и индивидуальные юридические выводы. Если применимость неясна, это прямо указано.

Автоматическая подборка — ежедневно с 13:00 до 13:15 Europe/Moscow, не более пяти карточек на подписчика. Карточки отправляются отдельными частями одного суточного пакета, успешные части учитываются в базе. После окна догоняющей отправки нет. Пустая подборка молчит. При потере ответа Telegram после принятия сообщения технически возможен повтор.

«НОВОЕ» — только новости с подтверждённой датой за последние 72 часа; для статей, документов, неизвестных и будущих дат метки нет. Свежесть пересчитывается при каждом показе.

- `/start` — подписка.
- `/latest` — три последних прошедших новый фильтр материала; ручной просмотр не расходует суточный пакет.
- `/status` — сбор, источники, последняя фактическая доставка и ближайшее окно по Москве.
- `/stop` — отписка.

## Источники

Шесть RSS: пять прежних правовых каналов КонсультантПлюс/ГАРАНТ и добавленный блог безопасности Касперского (`https://www.kaspersky.ru/blog/feed/`). Адреса — `collector/feeds.py` и миграция в `db/schema.sql`.

Четыре HTML-ресурса — `collector/survey_sources.json`: тематический раздел ГАРАНТа по защите персональных данных, безопасность сайтов опросов Kaspersky, справочный документ о персональных данных КонсультантПлюс, указанная владельцем страница Госдумы. Последняя на живой проверке недоступна и не считается работающим источником. Шесть прежних общих ресурсов убраны из каталога; при первом новом collector их старые записи деактивируются, данные сохраняются.

Разъяснения РКН — приоритетный кандидат, но его страницы при проверке не загрузились; они пока не подключены. Все новые ресурсы нужно проверять на доступность и реальную тематическую отдачу, а не увеличивать счётчик адресов.

## Сбор и обработка

`Источники → collector → PostgreSQL → worker → дневная очередь → Telegram`.

Единый проверяемый фильтр — `legal_news/relevance.py`, версия `privacy-risk-v2`. `collector/survey.py`, RSS и worker используют его одинаково. `legal_news/topics.json` хранит справочный тематический словарь; он не заменяет решение фильтра. Судебная практика по нужным рискам больше не исключается целиком. Связь с темой ищется в заголовке и начале содержательного текста, а не меню. Правила могут пропускать неявные связи; это не универсальный смысловой анализ.

Миграция добавляет оценку/причину/версию и таблицы суточных пакетов. Старые находки скрыты из выдачи, пока worker не оценит их новой версией; история находок, подписчиков и доставки не удаляется. Автоматическая доставка ждёт завершения переоценки активной очереди.

RSS сохраняют годовое окно первой загрузки и суточное перекрытие. HTML проверяет до шести страниц ресурса за проход; обычно повтор через семь дней, после ошибки — через шесть часов. Справочные материалы прошлых лет допустимы без метки свежести. Полный обход архивов и смысловое объединение разных пересказов одного события не гарантируются: точные дубли нормализованного URL/заголовка объединяются, разные формулировки могут потребовать ручной оценки.

## Обновление существующего ресурса Coolify

1. Использовать проверенную ветку/коммит из своего репозитория `katyaOMI/legal-news-bot`. До обновления проверить Git Source; прежний README указывал `main`.
2. Сохранить `TELEGRAM_TOKEN`, `SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_POSTGRES` и существующий том PostgreSQL.
3. База остаётся `desk_research`. Миграция добавляет поля и таблицы, не удаляет подписчиков, материалы и историю.
4. Выполнить Redeploy существующего ресурса. Контейнеры: `postgres`, `worker`, `bot`.
5. Существующая задача контейнера `worker`: `python main.py collector`, расписание `0 */3 * * *` (каждые три часа). Не создавать второй сборщик с тем же расписанием.
6. У задачи выполнить Execute Now, затем проверить `/status` и `/latest`. Ручной сбор может привести к настоящим сообщениям подписчикам.
7. Если часть источников недоступна, проверить их счётчики и ошибки; работа остальных продолжается.

Один Telegram-токен должен использоваться одним работающим обработчиком. Для проверки на компьютере не запускать production-бот параллельно.

## Локальный запуск и проверки

Python 3.12 и зависимости из `requirements.txt`. Для PostgreSQL задаётся `DATABASE_URL`, для Telegram — `TELEGRAM_TOKEN`. Реальные значения не писать в команды, документацию и Git.

```text
python main.py collector
python main.py worker
python main.py bot
python -m unittest discover -s tests -v
python checks/audit_release.py .
```

Предпросмотр живых источников без базы и Telegram:

```text
python checks/privacy_preview.py --limit 6
```

Он создаёт `work/privacy-preview.html`, JSON с карточками и снимок результатов. Эти файлы не публикуются.

После изменения правил можно переоценить те же публичные снимки без новых сетевых запросов: `python checks/privacy_preview.py --from-snapshot`. Исходные результаты сохраняются отдельно от актуально принятого набора.

Для сквозной SQL-проверки нужна временная локальная база PGlite и psycopg:

```text
npm install --prefix work/pgcheck --cache work/npm-cache --ignore-scripts --no-audit --no-fund @electric-sql/pglite @electric-sql/pglite-socket
python -m pip install --target work/python-packages --disable-pip-version-check "psycopg[binary]==3.3.6"
node checks/pg_server.mjs
```

В другом окне:

```text
python checks/privacy_pipeline.py
python checks/privacy_live_replay.py
```

Первый сценарий проверяет синтетические ошибки, даты и доставку. Второй воспроизводит публичные снимки последнего предпросмотра через настоящие таблицы и worker. Оба жёстко ограничены `127.0.0.1:55432`, создают отдельную схему и не отправляют Telegram. Остановка временной базы — запрос к `http://127.0.0.1:55433/shutdown`.

`checks/live_pipeline.py` — исторический сценарий старого правового контура, не приёмка версии 2.0. Актуальные SQL-проверки — privacy_pipeline и privacy_live_replay. Прежние команды survey_pipeline, survey_live_replay и preview_sources перенаправлены на новые проверки.

## Конфиденциальность

Логирование проходит через `db.redact`: значения секретных переменных, известные форматы ключей, пароли в URL, авторизационные заголовки и явно обозначенные Telegram ID маскируются до вывода. `db.fail_run` и поле ошибки источника сохраняют уже очищенный текст; `/status` дополнительно очищает старые заметки.

Для новых подписок сохраняется только необходимый для доставки chat_id; имя и username не собираются и не печатаются в журналах. Старые записи и старые журналы автоматически не удаляются. Рабочая база остаётся только на сервере.

При `ENABLE_MINI_APP`, не равном `1`, HTTP-корень возвращает лишь технический ответ, без чтения материалов и статистики. `/health` сохраняется. Явное включение `ENABLE_MINI_APP=1` открывает публичную ленту и должно быть осознанным решением владельца.

Дополнительная проверка текущих файлов и доступной истории Git:

```text
python checks/security_audit.py
```

Если Git отсутствует в PATH, можно указать его исполняемый файл через `--git`. Перед историческим аудитом получить актуальные refs из своего репозитория. Отчёт в `work/security-audit.json` содержит пути и названия правил, без значений найденных секретов. Проверка включает принудительно закоммиченные runtime-каталоги, которые обычный обход пропускает. Она охватывает только доступную историю, а не удалённые refs, журналы сервера или хранилища внешних сервисов.

Ни один сканер не гарантирует обнаружение всех произвольных секретов. Перед публикацией также проверяем состав файлов и назначение каждого артефакта. Историю с реальными секретами не переписываем и действующие ключи не отзываем без отдельного решения владельца.
