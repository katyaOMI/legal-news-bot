# Правовые новости для онлайн-исследований

Telegram-бот для мониторинга новых правовых публикаций РФ, связанных с онлайн-опросами
и обработкой персональных данных. Он собирает открытые RSS-ленты, отбирает материалы
по теме, объединяет повторные публикации и присылает новости подписчикам прямо в чат.

## Темы мониторинга

- Персональные данные, согласия и обезличивание.
- Хранение, локализация и трансграничная передача данных.
- Социологические опросы и маркетинговые исследования.
- Рекламные рассылки и маркировка рекламы.
- Иностранные агенты и ограничения, связанные со статусом организаций.

Темы и выражения для отбора находятся в `legal_news/topics.json`.
Первая версия использует бесплатные правила по заголовку и анонсу источника.
Платные API и модели ИИ не используются.

## Источники

Пять открытых RSS-лент двух издателей, доступных без подписки и API-ключа:

| Источник | RSS |
|---|---|
| КонсультантПлюс: горячие документы | https://www.consultant.ru/rss/hotdocs.xml |
| КонсультантПлюс: федеральное законодательство | https://www.consultant.ru/rss/fd.xml |
| КонсультантПлюс: новости для юриста | https://www.consultant.ru/rss/nw.xml |
| ГАРАНТ: новости | https://rss.garant.ru/categories/news/ |
| ГАРАНТ: федеральные документы | https://rss.garant.ru/hotlaw/federal/ |

Ссылки на источники сохраняются в каждой карточке. Судебная практика отсеивается
по категориям и признакам заголовка. Официальный API pravo.gov.ru предусмотрен
как дополнительный источник, но по умолчанию выключен.

## Как работает проект

`RSS → сборщик → PostgreSQL → тематический отбор → Telegram`

- `collector` загружает новые публикации и сохраняет подходящие материалы.
- `worker` применяет тематические правила и формирует карточки.
- `bot` управляет подписками и доставляет сообщения.
- PostgreSQL хранит материалы, ссылки, снимки исходных анонсов, подписки и историю доставки.

Один нормативный акт с совпадающими органом, видом, датой и номером объединяется
в одну карточку; ссылки на его появления сохраняются отдельно. Для других публикаций
объединяются совпадающие нормализованные заголовки. Доставка учитывается для каждого
подписчика. Если Telegram принял сообщение, но ответ потерялся, повтор всё же возможен.

## Команды Telegram

- `/start` — подписаться на новости.
- `/latest` — получить последние публикации.
- `/status` — узнать состояние обновления.
- `/stop` — отписаться.

Новости приходят в сообщения, сайт для чтения не нужен. HTTP-сервис бота используется
для совместимости с размещением; кнопка отдельной веб-ленты по умолчанию отключена.
При сбое источника отправляется одно сообщение о задержке, при восстановлении — одно
о возобновлении обновлений. Повторные проверки одного сбоя не создают новые уведомления.

## Развёртывание отдельного проекта в Coolify

1. Создайте новый GitHub-репозиторий и загрузите в его корень полный комплект проекта.
2. В Coolify создайте отдельный ресурс из этого репозитория, выбрав Docker Compose
   и файл `docker-compose.yml` в корне проекта.
3. В переменных окружения Coolify задайте `TELEGRAM_TOKEN` своего бота.
   Токен хранится только в настройках сервера; в файлы GitHub его не добавляйте.
4. Переменные `SERVICE_USER_POSTGRES` и `SERVICE_PASSWORD_POSTGRES` используются для
   учётной записи базы. Сохраните сгенерированные Coolify значения. Подключение
   `DATABASE_URL` передаётся контейнерам из Compose; имя новой базы — `legal_news`.
5. Запустите развёртывание. Должны работать сервисы `postgres`, `worker` и `bot`.
6. В Scheduled Tasks контейнера `worker` добавьте команду `python main.py collector`.
   Для ежедневного запуска в 09:00 по Москве: `0 6 * * *`, если часовой пояс задачи UTC.
7. Запустите эту задачу вручную для первой проверки. Откройте своего бота и нажмите
   `/start`, затем `/status` и `/latest`.

Это новый проект с новой базой. Подписчики и данные из прежнего приложения сюда
автоматически не копируются: читателям нужно подписаться через `/start`.
Если используется тот же Telegram-токен, остановите прежний экземпляр бота перед
запуском нового: два обработчика одного токена будут конфликтовать. Для параллельной
работы двух проектов требуются разные боты и токены.

Настоящие значения переменных задаются в Coolify. `.env.example` содержит только
пустые поля. Размещение на вашем сервере может иметь собственную стоимость;
проект не обращается к платным API и не оформляет подписки.

## Запуск отдельных блоков

Нужен Python 3.12 и PostgreSQL. Установите зависимости из `requirements.txt`.
Задайте в окружении `DATABASE_URL`; для бота также `TELEGRAM_TOKEN`.

```text
python main.py collector
python main.py worker
python main.py bot
```

Сборщик выполняет один проход и завершает работу. Обработчик и бот работают постоянно.
База создаёт таблицы при первом запуске. Пароли и токены нельзя передавать через
команды, сохраняемые в общей истории, или публиковать вместе с исходным кодом.

## Что хранится и что не публикуется

В рабочей базе хранятся публичные материалы, история получения, идентификаторы
подписчиков Telegram и отметки доставки. Рабочая база не является частью репозитория.
Папки данных, резервные копии, журналы, `.env`, ключи, зависимости и временные файлы
исключены из Git и сборочного контекста. В новый репозиторий загружаются только
исходники, настройки без значений секретов, документация и проверки.

## Границы первой версии

- Отбор выполняется по заголовку и анонсу, не по полному тексту документа.
- Общие названия без тематических слов могут быть пропущены.
- RSS содержит ограниченное окно записей. При суточной проверке или длительном сбое
  возможны пропуски; архив не догружается.
- На первом производственном запуске учитываются публикации после начала наблюдения.
- Дата публикации не является датой вступления в силу; последняя пока не извлекается.
- Скачивание оригиналов PDF, сравнение редакций и аналитические выводы ИИ не подключены.
- Смысловое объединение разных новостей об одном событии пока не выполняется.

Карточки сообщают о публикациях и не заменяют проверку первоисточника.

## Проверки

```text
python -m unittest discover -s tests -v
python checks/audit_release.py .
```

Модульные тесты не отправляют сообщения подписчикам. Дополнительный сценарий
`checks/live_pipeline.py` проверяет живые RSS, сохранение в локальном тестовом
ядре PostgreSQL (PGlite), обработку и формирование текста сообщения без отправки
в Telegram. Его база жёстко ограничена адресом `127.0.0.1:55432`; рабочий сервер
не используется. Для проверки нужны временные зависимости в `work/`:

```text
npm install --prefix work/pgcheck --cache work/npm-cache --ignore-scripts --no-audit --no-fund @electric-sql/pglite @electric-sql/pglite-socket
python -m pip install --target work/python-packages --cache-dir work/pip-cache "psycopg[binary]==3.3.6"
node checks/pg_server.mjs
```

Во втором окне выполните `python checks/live_pipeline.py`. Результат сохраняется
в `work/live-check-result.json`. Завершение тестового сервера — запрос к
`http://127.0.0.1:55433/shutdown`. Папка `work/` не публикуется.

Проверка на секреты статическая: она выявляет известные форматы и опасные файлы,
но не даёт абсолютной гарантии отсутствия всех возможных конфиденциальных данных.
После добавления новых файлов проверку следует повторить.
