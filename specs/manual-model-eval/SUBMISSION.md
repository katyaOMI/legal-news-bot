# Учебный отчёт по проверке качества Telegram бота

Проект: Telegram-бот о правовых рисках, приватности и безопасности онлайн-опросов при работе из России. Репозиторий — [legal-news-bot](https://github.com/katyaOMI/legal-news-bot). В рамках задания добавлена локальная проверка сохранённых ответов моделей; внешняя модель в рабочую рассылку не подключалась.

## Спецификация и второе мнение

Подготовлена спека отбора с решениями «подходит / не подходит / нужна проверка», объяснениями и цитатами. Kimi K3 (режим «Быстрый» по скриншоту, название K3 по уточнению владельца) проверила черновик 0.1. Основной агент разобрал все 22 замечания: полезные уточнения учтены, неподтвердившиеся противоречия отклонены с объяснениями. Полная редакция 0.2 утверждена владельцем до кода. Позже владелец согласовал [сокращённую спеку 0.3](SPEC.md) для пяти уже полученных примеров из-за длительности ручных прогонов; историческая 0.2 сохранена.

Разбор первой рецензии — [KIMI-REVIEW.md](KIMI-REVIEW.md). Kimi не рецензировала сокращённую редакцию 0.3, и это не заявляется.

## Сравнение и выбор

Обе модели получили один и тот же пакет E01–E05 с прежним эталоном и выключенным поиском по подтверждению владельца. Владелец до раскрытия сервисов выбрал вариант A — отклонить явно постороннюю новость о больничном. После раскрытия это DeepSeek.

| Результат на пяти примерах | Kimi | DeepSeek |
|---|---:|---:|
| Совпадение решений с эталоном | 4/5 | 5/5 |
| Валидный формат | 5/5 | 5/5 |
| Ошибочное принятие посторонних материалов | 0 | 0 |
| Лишнее откладывание на проверку | 1 | 0 |
| Скорость | не измерена | не измерена |
| Токены / цена API | не измерены | не измерены |

Для дальнейшего учебного эксперимента выбран сервис **DeepSeek**: на этих примерах он не отложил постороннюю новость без необходимости. Точная версия/режим DeepSeek не подтверждены. Новые платные API не подключались; сравнение выполнено вручную в доступных чатах. Это не подтверждение бесплатности будущего API.

Подробности — [RESULTS.md](RESULTS.md). Ограничения: всего один положительный пример, нет эталонных review и повторов устойчивости, объём уменьшен после частичного получения ответов, возможное узнавание авторства при ручном переносе. Скорость не измерена — эта часть задания остаётся невыполненной, цифры не придумывались. Общая надёжность и юридическая точность на всём потоке не доказаны; решение о зачёте принадлежит преподавателю.

## Реализация и проверка результата

Локальный `checks/model_eval.py` проверяет JSON, поля, ID, цитаты и российское основание, считает виды ошибок. Неполный отчёт явно не пригоден для сравнения, диагностическое предупреждение об опасном accept сохраняется даже при невалидной/повторной строке. Неизвестное время не заменяется нулём. Нет обращений к API, рабочей базе или Telegram.

Созданы отдельные локальные коммиты:

- E1 `8f43ec3` — проверка и тесты.
- E2 `fda2060` — спецификация и учебный выбор DeepSeek.
- E3 — исправления и разбор рецензии кода; актуальный SHA указан в progress.md.

DeepSeek выполнил статическую рецензию E1/E2 по предоставленным файлам. Основной агент воспроизвёл и исправил проблему счётчика невалидного review, уточнил статус неполных метрик и диагностику обязательного поля. Предложение обнулить предупреждение об опасном accept не принято, чтобы не скрывать проблему. [Разбор всех замечаний](DEEPSEEK-REVIEW.md).

После исправлений прошли **77 тестов**, включая 14 для нового инструмента. Те же сохранённые ответы локально дали прежние 4/5 и 5/5 без новых запросов к моделям. Повторной рецензии исправленного E3 второй моделью не было. Исходные ответы, эталон, скриншоты и технические отчёты сохранены в исключённой из Git папке work, без данных подписчиков и рабочей базы.
