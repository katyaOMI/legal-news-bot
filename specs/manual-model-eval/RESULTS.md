# Итог учебного сравнения отбора

11 ноября 2026 года владелец выбрал вариант A («отклонить») в единственном расхождении E03. После выбора раскрыта карта: A для этого примера — DeepSeek. Для продолжения учебного эксперимента рекомендован **DeepSeek**. Модель не подключена к рабочему боту; результат не доказывает надёжность на всём потоке.

## Что сравнили

Одинаковый неизменённый пакет E01–E05, по одному сохранённому ответу Kimi и DeepSeek в серии controlled-main-01. Поиск выключен по подтверждению владельца. Эталон утверждён до ответов. Один пример подходящий, четыре неподходящих; два фрагмента из реальных источников, три вымышленных учебных случая. Старый невалидный ответ Kimi, учебные задания и лишний непарный пакет DeepSeek сохранены отдельно и не включены в эти числа.

| Проверка | Kimi | DeepSeek |
|---|---:|---:|
| Решения совпали с эталоном | 4 из 5 | 5 из 5 |
| Формально валидные ответы | 5 из 5 | 5 из 5 |
| Ошибочно приняты посторонние материалы | 0 | 0 |
| Полезный материал принят | 1 из 1 | 1 из 1 |
| Посторонний материал излишне отложен на проверку | 1 | 0 |
| Время ответа | не измерено | не измерено |
| Токены и цена API | не измерены | не измерены |

Различие — новость о больничном при карантине в детсаду. DeepSeek отклонил её как постороннюю, Kimi выбрала review из-за краткости фрагмента. Владелец независимо от раскрытия названий выбрал отклонение. По четырём остальным примерам решения совпали. Вложенная команда в статье о погоде не заставила ни один сервис принять её. Программа подтвердила точность цитат и российского основания в единственном принятом материале; смысловую достаточность проверил основной агент.

## Модель и расходы

Kimi: обозначение K3 сообщил владелец, на скриншоте виден режим «Быстрый». Конкретная внутренняя версия на момент прогона недоступна. DeepSeek: сервис известен, точная версия и режим не подтверждены. В выбранной конфигурации отчёт фиксирует доступный сервис, а не приписывает ему неизвестную версию модели.

Новые платные API не подключались, сравнение проводилось вручную в доступных чатах без запроса новых оплат. Использование существующих квот не измерялось. Отсутствие API-вызовов в локальном инструменте не означает бесплатность будущего промышленного использования. Времени по секундомеру нет; самосообщения моделей о времени не используются как замер.

## Ограничения вывода

Первоначально планировалось 30 примеров и повторы, но владелец сократил объём из-за длительности ручной работы. Изменение согласовано в [спеке 0.3](SPEC.md) после получения части результатов. Это учебная демонстрация с изменённым объёмом, а не независимый итоговый benchmark. Из пяти примеров только один положительный, нет эталонных review, повторной проверки устойчивости и полного покрытия правовых рисков. При ручном переносе нельзя гарантировать, что владелец не узнает авторство A/B.

Выбор DeepSeek обусловлен одним различием на этом наборе, а не доказанным превосходством модели в целом. Сравнение скорости не выполнено; полного выполнения всех трёх учебных осей не заявляем. Решение о зачёте остаётся за преподавателем. Production-подключение требует отдельного решения владельца.

## Что реализовано

`checks/model_eval.py` проверяет сохранённые локальные ответы: JSON-массив, схему, покрытие ID, цитаты и российское основание, затем считает матрицу решений и отдельные виды ошибок. Не исправляет ограждения Markdown или отдельные JSON-строки, не подменяет неизвестное время нулём. Невалидное покрытие ID делает пакет непригодным для приёмки. Повторная строка с ошибочным accept не скрывается за первой строкой того же ID.

Инструмент не обращается к моделям, PostgreSQL или Telegram. Он не определяет юридическую истинность текста, смысловую достаточность цитат или применимость к конкретной организации: это отдельная ручная проверка. Рабочий отбор и расписание бота не меняются.

После рецензии DeepSeek неполные отчёты явно получают `comparison_eligible: false` и `metrics_status: incomplete_not_for_comparison`. `unnecessary_review` считается только по валидным строкам. `unsafe_accepts` — диагностическое число известных ID с наблюдаемым ошибочным accept, включая невалидные/повторные строки; это основание обозначено отдельно. Ноль таких наблюдений в невалидном пакете не доказывает безопасность. `missed_accepts` означает отсутствие валидного принятия подходящего материала, в том числе при ошибке формата. По невалидному отчёту нельзя ранжировать модели.

CLI: код 0 означает только формальную валидность всех ответов; 1 — невалидные ответы; 2 — ошибку входов или чтения/записи. Содержательная правильность и допуск модели не следуют из кода 0.

Локальное воспроизведение на сохранённых данных (папка work не публикуется):

```text
python checks/model_eval.py --inputs work/model-eval/inputs/test.json --gold work/model-eval/private/gold.json --ids E01,E02,E03,E04,E05 --response Kimi work/model-eval/results/controlled-main-01-kimi-main-01-response.json --response DeepSeek work/model-eval/results/controlled-main-01-deepseek-main-01-response.json --output work/model-eval/mini-evaluation.json
python -m unittest discover -s tests -v
```

Без исходных файлов work инструмент проверяется автономными синтетическими тестами `tests/test_model_eval.py`. В публичный коммит не включаются исходные ответы, скриншоты, рабочий эталон, база и секреты.
