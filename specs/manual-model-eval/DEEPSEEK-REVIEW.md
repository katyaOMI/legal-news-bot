# Разбор рецензии DeepSeek по коду

11 ноября 2026 года владелец передал независимую статическую рецензию на E1 `8f43ec3` и E2 `fda2060`. Рецензент прямо указал, что читал только предоставленные тексты, не открывал репозиторий/сервер и не запускал тесты. Его точная модель и режим не подтверждены. Исходная рецензия сохранена без изменения в `work/model-eval/reviews/deepseek-code-E1-E2.txt`, вне Git.

## Проверка замечаний основным агентом

| № | Вердикт | Проверка и итог |
|---|---|---|
| 1 | Частично подтверждено: отчёту не хватало явного статуса | Неизвестный ID уже не попадал в содержательные счётчики. Ошибка покрытия намеренно делала весь пакет невалидным. Предупреждение о наблюдаемом опасном accept специально учитывает известные ID даже в невалидных/повторных строках. Обнулять его нельзя — это скрыло бы видимую проблему. Добавлены `comparison_eligible` и `metrics_status`: при любом невалидном ответе отчёт не пригоден для сравнения. Добавлено явное основание `unsafe_accepts_basis`, чтобы диагностическое предупреждение не принималось за оценку качества валидных строк. Новые тесты проверяют лишний/повторный ID и сохранение предупреждения |
| 2 | Подтверждено и исправлено | Воспроизведён reject-эталон с решением review и выдуманной цитатой: до исправления unnecessary_review был 1 при невалидной строке. Теперь этот счётчик учитывает только валидные строки; невалидность отражается отдельно. Принятие полезного материала без валидного ответа по-прежнему не засчитывается, поэтому missed_accepts включает такой пропуск |
| 3 | Нарушение обязательности опровергнуто; диагностика улучшена | Поле russia_basis уже было обязательным по точному сравнению FIELDS. При его отсутствии строка имела ошибку fields, что подтверждал существующий тест. Проверка содержимого только при наличии защищала от KeyError, а не делала поле опциональным. Добавлена отдельная ошибка missing_russia_basis; null остаётся допустимым значением. Требование и политика не менялись |
| 4 | Дефекта нет, граница подтверждена | Рецензент сам отделил замечание от ошибки. Программа проверяет точность цитат, человек — их смысл, применимость и юридические утверждения. Это соответствует спеке; автоматическая юридическая экспертиза не добавлялась |
| 5 | Необязательное улучшение; менять не требуется | subTest уже передаёт параметр raw, поэтому при падении unittest показывает конкретный вход. Разделение в отдельные методы не меняет покрытия. Добавлены именно недостающие регрессии по метрикам, а не дубли существующих тестов |

Дополнительно документированы коды завершения CLI: 0 — ответы формально валидны, 1 — невалидный ответ, 2 — ошибка входов/чтения/записи. Код 0 не означает совпадения с эталоном, смысловой правильности или допуска модели к боту.

## Проверки после исправления

До изменения кода новые проверки воспроизвели старое поведение: счётчик невалидного review и отсутствие явных статусов/детальной диагностики. После исправления весь набор из **77 модульных тестов прошёл**, из них 14 — для локального инструмента.

Те же сохранённые ответы повторно проверены программой без обращений к моделям. Результат мини-теста не изменился: DeepSeek 5/5, Kimi 4/5; ответы обоих формально валидны, наблюдаемых опасных accept нет, у Kimi один валидный избыточный review. Время остаётся null. Это повтор локальной проверки файлов, не новый сравнительный прогон модели.

Рецензия DeepSeek относится к E1/E2 до исправлений. Исправления проверены основным агентом тестами; повторной внешней рецензии E3 не было и она не заявляется. Учебный набор, эталон и запрос не менялись. Новых API, изменения рабочего отбора бота, обновления GitHub или сервера на этом этапе нет. Статус локального коммита E3 — в progress.md.
