# Учебное сравнение отбора на пяти примерах

Владелец утвердил сокращение ответом «да» 11 ноября 2026 года после предложения остановить новые прогоны и использовать пять уже полученных одинаковых примеров. Новых запусков для сравнения не требуется. Предыдущий полный план сохранён в [SPEC-0.2.md](SPEC-0.2.md); он больше не определяет объём эксперимента. Действующая корневая SPEC 2.0 и поведение рабочего бота не меняются.

## Цель и границы

Сравнить Kimi и DeepSeek на тематическом отборе материалов о правовых рисках, приватности и безопасности онлайн-опросов при работе из России. Использовать только первый пакет E01–E05 серии controlled-main-01: по одному уже сохранённому ответу каждого сервиса с выключенным поиском по подтверждению владельца. Исходный невалидный ответ Kimi с неизвестными настройками сохраняется отдельно и не заменяется.

Правила релевантности остаются прежними: персональные данные, согласия, хранение/удаление, локализация/передача и безопасность опросов; методология, NPS, рекрутинг и общие новости ИИ без целевого риска исключены. Для зарубежного события нужна подтверждённая российская связь. Ответ: accept/reject/review с причиной и точной цитатой для accept. Никаких выдуманных юридических выводов. Внешняя модель к рабочему боту не подключается.

## Состав и ограничения мини-теста

Пять примеров первого пакета: один подходящий, четыре неподходящих по заранее утверждённому эталону; два реальных публичных фрагмента и три синтетических. Эталон и запрос не меняются. В наборе нет эталонного review, полноценной проверки всех категорий, достаточного числа полезных материалов и повторов для оценки устойчивости.

Объём сокращён после получения части ответов по просьбе владельца из-за затрат времени. Это учебная демонстрация, не независимый итоговый benchmark. Результаты нельзя обобщать на весь поток бота или превращать в проценты доказанной юридической точности. Ранее полученный второй пакет DeepSeek и учебные примеры остаются дополнительными материалами, но не входят в парное сравнение пяти примеров и не используются для улучшения результата только одного сервиса.

## Как оцениваем

1. Программно проверить единый JSON-массив, точные поля и типы, все пять ID по одному, допустимые решения и дословность цитат/российского основания. Невалидный ответ сохраняется как ошибка, молча не исправляется.
2. Сравнить решения с прежним эталоном. Отдельно показать ошибки опасного принятия, пропуски подходящего материала и избыточное review. Значения показывать как числа из пяти, без утверждения общей надёжности.
3. Перед раскрытием сервисов показать владельцу A/B по единственному расхождению E03; полные пары всех пяти примеров доступны на одной локальной странице. Для остальных примеров решение совпадает, проверка смысла цитат выполняется основным агентом на ранее утверждённом эталоне. Сохранить выбранную владельцем оценку; не заявлять, что он отдельно оценил каждое объяснение.
4. Карта A/B уже создана отдельно по каждому ID и не меняется ради результата. Полной слепоты при ручном переносе не гарантируем. После оценки раскрыть сервисы и дать обоснованную учебную рекомендацию, указав ограничения. Выбор для эксперимента не разрешает production-подключение.

## Скорость и стоимость

Пользовательского замера времени нет. Записать «не измерено», медиану и задержку не придумывать. Самооценка времени моделью не является измерением. Новых оплачиваемых API не подключали; сравнение выполнено вручную в доступных чатах без запрошенных новых оплат. Токены, API-тариф и цена промышленного использования не измерялись. Расход существующих квот не выдаётся за ноль.

Таким образом, часть задания о сравнении скорости остаётся ограничением отчёта. Не утверждать, что учебное требование по всем трём осям полностью выполнено; решение о зачёте принадлежит преподавателю.

## Реализация после оценки A/B

E1 — локальный инструмент `checks/model_eval.py` проверяет сохранённые ответы и выводит отчёт. Он не вызывает API, не читает production-настройки, не подключается к PostgreSQL и Telegram. Значимые тесты — `tests/test_model_eval.py`: неверный JSON/массив, лишние/пропущенные/повторные ID, неправильные поля/типы, ложные цитаты, невалидный russia_basis, подсчёт метрик и отсутствие замены неизвестного времени нулём. Формальные проверки не подменяют смысловую оценку и юридическую экспертизу.

E2 — короткий отчёт с выбором по мини-тесту, причинами, названием доступного сервиса/режима и неизвестными параметрами. У Kimi обозначение K3 сообщено владельцем, «Быстрый» виден на скриншоте; точная версия/режим DeepSeek не подтверждены, их нельзя придумывать. Оформить отдельные коммиты задач после проверок. Не включать существующие чужие изменения и приватный work без проверки состава.

Перед публикацией — проверки и аудит по [AGENTS.md](../../AGENTS.md). Сохраняются исходные ответы и прежние незакоммиченные документы. После коммита дать DeepSeek утверждённую спеку, diff/код и результаты тестов для второго мнения, разобрать каждую находку с основным агентом. Это отдельная будущая рецензия кода, а не новые прогоны сравнения. Сохранить прежнюю рецензию Kimi на 0.1 и разбор; не утверждать, что Kimi проверила сокращённую редакцию 0.3.

## Что означает готовность

Оценка A/B владельцем получена; краткий отчёт различает измеренное и неизвестное; локальный инструмент проверен тестами; коммиты и второе мнение по коду оформлены. До этого задание не объявлять полностью выполненным. Публикацию GitHub и реальную работу сервера указывать раздельно. Redeploy версии 2.0 остаётся отдельным неподтверждённым этапом.
