# Работа над тематическим ботом

Telegram-бот помогает замечать риски приватности, безопасности и доступности цифровых сервисов и интернета. Стек — Python/PostgreSQL/Docker Compose/Coolify; цель продукта описана в PRD.md, процессы — в README.md.

- Общаемся и пишем пользовательские тексты по-русски.
- При возобновлении работы читай последнюю веху progress.md и KANBAN.md; перед запуском, изменением путей и обновлением — README.md. Инвентарь файлов ведётся только в README.md.
- Перед изменением поведения читай SPEC.md; история её согласования описана там. Не выдаём итоговое утверждение за предварительное. Цель продукта — PRD.md.
- SPEC 2.2: после оценок 19 ноября основной фокус — личные данные в интернете, сбор данных, согласия и приватность. Общая инфраструктура и атаки без этой связи исключаются. Исторический фокус 17 ноября: интернет, цифровые сервисы, приватность, безопасность и доступность; связь с опросами не обязательна. ИИ — только влияние на приватность/безопасность. Методологию, NPS, рекрутинг и частные правовые истории без цифровой связи исключаем. Серверное обновление не подтверждено.
- «НОВОЕ» — только новости с подтверждённой датой не старше 72 часов; не первая доставка. Ежедневное окно 13:00–13:15 МСК, до пяти карточек.
- Сохраняем подписки, существующую базу и историю доставки.
- Модели и платные API без отдельного решения не подключаем.
- Учебный PR № 7 оставить открытым, не сливать в main и не удалять ветку без нового прямого поручения владельца. Это не обновление бота.
- Учебное сравнение сокращено до пяти уже оценённых примеров: отменённые 30 примеров и повторы без нового поручения не возобновлять. Итог — specs/manual-model-eval/RESULTS.md.
- Exa/Tabstack настраиваются только как инструменты Codex, не сборщика бота. Не считать запись MCP подтверждением работы; актуальный статус и следующий шаг — progress/KANBAN.
- Не называем поиск по правилам универсальным смысловым анализом; проверяем результаты на реальных страницах.
- Один номер задачи — один коммит. Поведенческие тесты обязательны.
- Перед публикацией: `python -m unittest discover -s tests -v` и `python checks/audit_release.py .`.
- Локальная SQL-проверка — `checks/privacy_pipeline.py` с временной базой из README.
- Предпросмотр — `checks/privacy_preview.py`; он не отправляет Telegram.
- Не коммитим work/, ключи, токены, .env, дампы и данные подписчиков.
- Перед внешней публикацией проверяем содержимое и доступную историю через checks/security_audit.py; отчёты не должны содержать значения секретов.
- Для журналов и диагностики используем db.redact. Не печатаем имена, usernames и chat_id подписчиков; не включаем имена в новые подписки без необходимости.
- Публичную веб-ленту по умолчанию не включаем. Переменные и рабочую базу сервера не выгружаем для отладки.
- В конце этапа синхронизируем README, KANBAN и progress. Не удаляем чужие файлы.
