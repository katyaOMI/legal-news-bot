# Работа над тематическим ботом

- Общаемся и пишем пользовательские тексты по-русски.
- SPEC.md — действующее поведение и задачи T1–T3; версия 1.0 разрешена владельцем в чате 9 ноября 2026 года.
- Уточнение SPEC 1.1 / T4: по оценке владельца расчёты количества респондентов и размера выборки исключены из подборки.
- README.md — запуск, источники и обновление. KANBAN.md — статусы. progress.md — последняя веха и следующий шаг.
- PRD.md — цель продукта и пользовательский сценарий.
- Продукт собирает новости и материалы об онлайн-опросах, исследованиях, респондентах, инструментах и данных.
- «НОВОЕ» означает впервые присланный материал, а не сегодняшнюю дату публикации.
- Сохраняем подписки, существующую базу и историю доставки.
- Модели и платные API без отдельного решения не подключаем.
- Не называем поиск по правилам универсальным смысловым анализом; проверяем результаты на реальных страницах.
- Один номер задачи — один коммит. Поведенческие тесты обязательны.
- Перед публикацией: `python -m unittest discover -s tests -v` и `python checks/audit_release.py .`.
- Локальная SQL-проверка — `checks/survey_pipeline.py` с временной базой из README.
- Предпросмотр — `checks/preview_sources.py`; он не отправляет Telegram.
- Не коммитим work/, ключи, токены, .env, дампы и данные подписчиков.
- Перед внешней публикацией проверяем содержимое и доступную историю через checks/security_audit.py; отчёты не должны содержать значения секретов.
- Для журналов и диагностики используем db.redact. Не печатаем имена, usernames и chat_id подписчиков; не включаем имена в новые подписки без необходимости.
- Публичную веб-ленту по умолчанию не включаем. Переменные и рабочую базу сервера не выгружаем для отладки.
- В конце этапа синхронизируем README, KANBAN и progress. Не удаляем чужие файлы.
